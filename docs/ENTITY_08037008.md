# Location-bound actor entity hierarchy at 0x08037008

## Scope

This document records the proven retail structure of the neutral `AActorEntity`-derived hierarchy beginning at `0x08037008`. The gameplay identity of these classes is not yet proven, so source names remain address/vtable-derived. The current source implementation is `include/entity_unk_08037008.hh` and `src/entity_unk_08037008.cc`.

## Base class

`UnkEntity37008` is a 0x44-byte abstract `AActorEntity` subclass with this proven tail layout:

| Offset | Type | Meaning |
| ---: | --- | --- |
| +0x30 | `ActorLocation *` | borrowed persistent location back-reference |
| +0x34 | `Box` | working/collision box |
| +0x3C | `u16` | value returned by virtual +0x34 |
| +0x3E | `u16` | runtime counter/state cleared by virtual +0x10 |
| +0x40 | `bool` | initialization/update flag |

The constructor at `0x08037008` calls `AActorEntity(game_object, location, 2, arg_3)`, stores `&location`, initializes the `Box` to zero, stores `arg_4` at +0x3C, clears +0x3E, and sets +0x40. The destructor at `0x08037048` writes `GetLocation()` back through `location_ref` before normal base destruction. This establishes two-way location persistence for the hierarchy.

`UnkEntity37008::SetBox(Box const&)` at `0x08037244` is also exact source. It copies the 8-byte `Box` into the embedded +0x34 field; the generated body is 0x0A bytes and the retail slot is completed by the normal 2-byte section alignment.

- +0x0C `GetBox()`: a 14x14 box centered on x and two pixels above y.

The complete +0x40 family is now behavior-recovered. Each method selects a weighted 4-byte action row, computes a randomized duration in seconds, optionally rotates facing, applies table-selected Q16 speed, updates animation if needed, and returns the duration. 7218 uses one 3-row table. 72E4 / 72A0 / 725C select between day/night groups of 5 / 7 / 13 rows respectively from the GameObject schedule state. Realistic member-function probes are exact-size for all four retail methods: 72E4 `0xA8`, 72A0 `0xA8`, 725C `0xA4`, 7218 `0x80`. Every probe differs in exactly **6 linked bytes**, and every difference is the same three-instruction register-order choice immediately after `func_080AB82C`: retail forms the selected row pointer from `r0` before preserving the index, while the compatibility compiler preserves the index first. The rest of each method matches. The whole family is therefore parked as one compiler-sensitive island rather than syntax-rouletted individually.

The 72E4 / 72A0 +0x3C pair is also behavior-recovered. The GameObject virtual at +0x144 returns a schedule-state view whose relevant packed fields are bytes +8/+9/+10: a 3-bit year value, packed season/day, and 5-bit hour. The methods accept hours 06:00 through 15:59, derive weekday as `(day + season * 30 + (year + 6) * 120) % 7`, require weekday != 0 for 72E4 or != 1 for 72A0, and require the state word at +0x00 to be zero. On success they build one of three fixed `ActorLocation`s from the concrete +0x44 2-bit variant, call `SetLocation`, and refresh animation zero; otherwise they call `SetMap(MAP_NONE)`. Scratch source with the packed-byte model reproduces the retail loads, bit extraction, range test, modulo path, and semantics, but the full functions remain nonmatching because retail saves/restores `r8` and uses a different register allocation. They are parked with that cause recorded.
